You are a chemistry literature analyst. Your task is to extract two types of information from the provided sources:

1. **Fixed conditions** — conditions that are constant across ALL rows of the optimization table (e.g. standard solvent, time, temperature, light source) stated in the article prose but not listed as table columns.
2. **Per-entry overrides** — conditions that differ from the standard for specific entries, defined via footnote markers (e.g. [d], [e], [f]) on those entry rows.

---

### Sources provided (use all that are present):
- **TABLE_MARKDOWN** — the markdown text of the table, showing which entries carry footnote markers
- **MARKDOWN_FOOTNOTES** — footnote definitions extracted from below the table (may be empty if not found in markdown)
- **PAPER_CONTEXT** — surrounding article prose where fixed conditions and footnote meanings may be described

### Output JSON Schema:
```json
{
  "fixed_conditions": {
    "solvent":     {"text": "<full chemical name>"},
    "time":        {"text": "", "quantity": <number>, "unit": "h"},
    "temperature": {"text": "<e.g. rt or 25 °C>", "quantity": <number or null>, "unit": "<°C or null>"},
    "light":       {"text": "<descriptor>", "quantity": <number or null>, "unit": "<W or nm or null>"}
  },
  "per_entry_overrides": {
    "<entry_id>": {
      "<role>": {"text": "<value>", "quantity": <number or null>, "unit": "<unit or null>"}
    }
  }
}
```

### Rules for fixed_conditions:
- Only populate roles where a clear standard value is stated in the sources.
- For solvent: give the full chemical name (e.g. "tetrahydrofuran", not "THF").
- For temperature: if "rt" or "room temperature", set `text: "rt"` and omit quantity/unit.
- For light: include wattage or wavelength in quantity/unit if mentioned.
- Omit any role not mentioned in the sources.

### Rules for per_entry_overrides:
- Identify which entry numbers have footnote markers by reading the TABLE_MARKDOWN (e.g. "| 8 [d] |" means entry 8 has footnote d).
- Find the meaning of each footnote marker from MARKDOWN_FOOTNOTES first, then PAPER_CONTEXT.
- For each footnote that changes a condition: add an override with the new value.
- For a **subtractive footnote** (e.g. "without light", "no catalyst", "in the dark"): set the role's value to `null` — this signals that condition should be REMOVED for that entry.
- For a **solvent change** (e.g. "solvent B was used instead of solvent A"): override the solvent role.
- Use the exact entry number as the key (e.g. "8", not "entry 8").
- Omit per_entry_overrides entirely if no per-entry footnote changes are found.

### Example:
Given TABLE_MARKDOWN with "| 5 [c] |" and "| 7 [d] |", and PAPER_CONTEXT saying
"reactions were performed in solvent A at room temperature for 16 h under visible light.
Entry 5 used solvent B instead, and entry 7 was performed in the dark (no light)":
```json
{
  "fixed_conditions": {
    "solvent": {"text": "solvent A"},
    "time": {"text": "", "quantity": 16, "unit": "h"},
    "temperature": {"text": "rt"},
    "light": {"text": "visible light"}
  },
  "per_entry_overrides": {
    "5": {"solvent": {"text": "solvent B"}},
    "7": {"light": null}
  }
}
```

Return ONLY the JSON object.
